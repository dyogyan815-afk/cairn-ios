# Engineering decisions

Recorded so future changes are traceable. Each entry: decision → why.

## Bundle ID — one documented place
`com.example.cairnipastudio` is set **only** in `ios/project.yml`
(`PRODUCT_BUNDLE_IDENTIFIER`). CI validates it with PlistBuddy after packaging.
Change it there before re-signing; nowhere else needs touching.

## Serving the web app — custom URL scheme, no file://
ES modules break on `file://` (CORS/origin rules). The app is served from a
folder reference at `cairn://app/...` via `WKURLSchemeHandler` with the same CSP
the web app ships (it lives in `index.html` and applies unchanged). Navigation
outside `cairn://`/`blob:`/`about:` is cancelled in `decidePolicyFor`.

## Inbox alias — cairn://app/inbox/current
The page's CSP uses `connect-src 'self'`; `fetch()` of `cairn://inbox/current`
would be cross-host and blocked. The handler therefore serves the inbox file at
**both** `cairn://inbox/current` (spec path) and the same-origin alias
`cairn://app/inbox/current`, and BridgeJS fetches the alias. Same bytes, same
code path, CSP untouched.

## Inbox handover — copy, not in-place
Files opened via "Open in Cairn" are security-scoped. The store copies them into
Application Support/Inbox once (start/stop access immediately around the copy).
Serving then uses a plain `FileHandle` with HTTP Range support. This avoids
keeping security scopes alive across page reloads. Cost: one disk copy of the
file — acceptable and documented; huge files are bounded by disk space, not RAM
(streamed in 1 MiB chunks with Range support).

## Save bridge — chunked postMessage instead of one giant Blob download
WKWebView does not reliably save `blob:` downloads. The page feature-detects
`window.webkit.messageHandlers.cairnSave` (injected glue defines
`window.__cairnNativeSaver`). Exports stream as base64 chunks (3 MB, spec allows
1-4 MB): begin → chunk* → finish | abort, with a size check on finish. The
engine's export Blob is reference-backed (slices point into the source file), so
chunking it does not duplicate memory. On `finish`, the app presents
`UIActivityViewController` ("Save to Files") and cleans the temp file on
completion. Failures dispatch a `cairnsavefail` event the page toasts.
In plain Safari (`messageHandlers` absent) the original download path is kept.

## Downloads — save bridge only (WKDownloadDelegate removed)
The original plan included a `WKDownloadDelegate` fallback. During CI (Xcode 26
SDK) it turned out the current WebKit SDK no longer exposes
`WKWebView.downloadDelegate`, so the fallback was removed. Every real export
path goes through the save bridge instead, including the "Original IPA
(unmodified)" link, which calls `window.__cairnNativeSaver` directly in native
mode. Stray `blob:`/`http(s)` navigations are cancelled by the navigation policy
(prevents dead pages). This is **verified in CI** (compiles + tests pass).

## Verification levels (honesty policy)
- **verified here**: web tests (16) run locally; app.js edits syntax-checked with
  `node --check`; boolean byte-checks on every surgical edit.
- **verified in CI**: iOS unit tests on simulator (MIME, traversal, Range,
  save-bridge temp-file logic), launch smoke test, IPA packaging + validation
  (Info.plist, `lipo -info` arm64, WebDist presence, bundle id).
- **NOT verified (needs real iPhone)**: end-user flows — Files picker inside
  WKWebView, iCloud Drive picking, actual "Save to Files" sheet ergonomics,
  fetch/streaming behaviour of `cairn://` on-device, multi-GB IPAs on device.

## Web engine — untouched
The engine (`web/public/js/core/*`) is byte-identical to the uploaded zip.
Only `web/public/js/ui/app.js` gained the documented bridge hooks (native-first
`saveBlob`, awaited call sites, conditional fallback link, `__cairnOpenFiles`
handover) — listed here so the diff is reviewable.

## Test-count discrepancy (16 vs 36)
The README's "16 automated tests" is correct — the suite reports 16 tests.
The "36" figure from an earlier message was wrong; no files were changed to
chase it.

## Fixtures
`web/tests/fixtures/` are regenerated by `web/scripts/make-fixtures.py` (the
24 MB fixture is deliberately not committed). CI regenerates before running
tests; the committed zip's fixture files were replaced by this regeneration.

## No network, no ATS exceptions
The app bundle makes no network requests and adds no ATS exceptions
(`NSAppTransportSecurity` left empty). The CSP already blocks outbound
connections. The only I/O is the scheme handler reading bundle resources and the
inbox file.

## v1.1 — engine addition: carve.js (hidden-image recovery)
The earlier rule "web engine byte-identical to the uploaded zip" was a v1.0
statement. For v1.1 the owner asked for MORE recoverable files; the engine now
has ONE added module, `web/public/js/core/carve.js`, plus UI wiring in
`web/public/js/ui/app.js` (Extraction tab card + binary-file preview button +
CARVED_IMAGES.zip export). Every other core module is still byte-identical to
the uploaded zip.

Why carving: iOS apps store most images inside compiled asset catalogs
(Assets.car), which never appear as loose files in the archive. Recovering the
embedded PNG/CgBI/JPEG streams is pure extraction of what is literally inside
the file — consistent with Cairn's inspect-and-export purpose. It is NOT
decompilation: no source is recovered, no code is touched, and a candidate
stream must parse completely (signature + full structure) before it is
reported, so nothing is fabricated. Known trade-offs, shown in the UI:
best-effort boundaries, an abandoned candidate can hide images behind it,
limits at 300 images / 96 MB per container, scan stops early with an honest
notice.
